# 日森精工專案開發與版本安全規範

當前專案在開發與修正時，必須嚴格遵循以下行為約束與安全規則，以防止版本覆蓋或修改錯誤：

## 1. 📂 確立單一數據源與路徑規範
*   **限定操作 G 槽**：所有檔案讀寫、替換與刪除，必須一律針對 G 槽路徑 `G:\我的雲端硬碟\ai\日森精工` 目錄下的檔案進行。
*   **禁止 C 槽同步**：禁止執行 any 自動或手動的本機同步腳本（如 `robocopy`、`cp -r`等將 C 槽覆蓋回 G 槽的操作）。
*   **C 槽僅作鏡像**：若為防止 VS Code 路徑混亂需寫入 C 槽 `C:\ai\日森精工`，必須手動進行「雙向等值寫入」，絕對禁止使用覆蓋式同步。

## 2. 🌿 變更前 Git 自動備份與防護
*   在對 `index.html`、`portal.html` 或任何模組（`modules/`）進行變更前，AI 助手必須：
    1.  檢查工作區狀態 `git status`。
    2.  將當前穩定版本做一個本地提交備份（如：`git add .` 與 `git commit -m "變更前備份：[簡短描述]"`）。
*   若變更後網頁出現語法錯亂、標籤不對稱或版面異常，必須立即執行 `git checkout .` 回滾至上一個穩定備份，嚴禁交付有瑕疵的程式碼。

## 3. 📝 變更流程控制
*   對於任何非微調的代碼變更，AI 助手必須進入 **Planning Mode**：
    1.  先撰寫並更新 `implementation_plan.md`，詳列修改目標、受影響檔案的精確行數與修改代碼。
    2.  等待使用者在對話中確認同意後，再進行實際檔案修改。
*   每次修改完成後，必須自動執行 HTML 標籤配對檢查與 JS 語法驗證。
